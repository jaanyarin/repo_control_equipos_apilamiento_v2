## 1. Objetivo del Hito

Completar las pantallas de la aplicación mobile que no tenían contraparte en el frontend móvil, cubriendo todos los módulos del backend que carecían de interfaz móvil: catálogos (marcas, proveedores, tipos de equipo, sedes), campañas, roles, usuarios, auditoría y configuración.

---

## 2. Cambios Realizados

### 2.1 Nuevo: `CatalogScreen.js` — Componente Genérico de Catálogo

| Archivo | Propósito |
|---|---|
| `mobile/src/screens/CatalogScreen.js` | Componente reutilizable para CRUD de catálogos simples con búsqueda, lista, creación, edición y eliminación |

**Funcionalidad:**
- Búsqueda local por campos configurables
- Pull-to-refresh
- FAB para agregar
- Modal (Dialog) para crear/editar con campos dinámicos
- Eliminación con confirmación
- Manejo de estados: loading, error, empty

### 2.2 Nuevas Pantallas que usan `CatalogScreen`

| Pantalla | Archivo | Endpoint | Campos |
|---|---|---|---|
| **Marcas** | `MarcasScreen.js` | `GET/POST/PUT/DELETE /marcas` | nombre (req), código |
| **Proveedores** | `ProveedoresScreen.js` | `GET/POST/PUT/DELETE /proveedores` | razónSocial (req), RUC (req), código |
| **Tipos de Equipo** | `TiposEquipoScreen.js` | `GET/POST/PUT/DELETE /tipos-equipo` | nombre (req), código, descripción |
| **Sedes** | `SedesScreen.js` | `GET/POST/PUT/DELETE /sedes` | nombre (req), código, dirección |
| **Roles** | `RolesScreen.js` | `GET/POST/PUT/DELETE /roles` | nombre (req), descripción |

### 2.3 Nuevas Pantallas Especializadas

| Pantalla | Archivo | Funcionalidad |
|---|---|---|
| **Campañas** | `CampanasScreen.js` | Listado con búsqueda, chips de estado (activo/cerrado), botones Activar/Cerrar por campaña, eliminación |
| **Usuarios** | `UsuariosScreen.js` | Listado con búsqueda, chips de rol por color (Super Admin=#6a1b9a, Admin=#1565C0, Usuario=#2e7d32), eliminación |
| **Auditoría** | `AuditoriaScreen.js` | Listado de últimos 100 eventos con búsqueda, chips de tipo por color (error=rojo, create=verde, update=naranja), detalle expandido |
| **Configuración** | `SettingsScreen.js` | Formulario para configurar URL de API (persistencia en SecureStore), restablecer a valor por defecto, información del sistema |

### 2.4 Modificaciones a Componentes Existentes

| Archivo | Cambio |
|---|---|
| `api.js` | Exportado `BUILT_IN_API_URL` como constante nombrada |
| `AppNavigator.js` | Agregado 4to tab "Catálogos" con menú de 9 botones. Agregadas 9 nuevas rutas al MainStack |
| `HomeScreen.js` | Corregido "Ingreso de PSR y OSR" para navegar a Campanas (antes era EquiposList) |

### 2.5 Estructura de Navegación Actualizada

```
BottomTabs:
  - Inicio (HomeScreen)
  - Equipos (EquiposListScreen)
  - Catálogos (CatalogoTabScreen → menú con 9 botones)
  - Perfil (PerfilScreen)

MainStack (push screens):
  - EquipoDetail, RegistrarAveria, AtenderAveria
  - Marcas, Proveedores, TiposEquipo, Sedes
  - Campanas, Roles, Usuarios, Auditoria, Settings
```
